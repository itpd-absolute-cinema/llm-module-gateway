# QR-04: Reject Unauthorized Plugin Administration

With distinct admin and gateway credentials, every valid-shaped admin request without the correct admin bearer receives 401, or 503 when no admin key is configured, without changing saved state.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Authenticity
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A caller without the admin credential, including an ordinary gateway user.

### Stimulus

The caller submits list, inspect, upload, replace-options, set-enabled, and delete requests with valid paths, content types, and bodies.

### Environment

One `prototype gateway` process uses distinct admin and gateway test credentials; repeat with chat authentication enabled and disabled after restart, and with the admin key unset or empty.
This bounds the simple login of [DEC-007](../../decisions.md#dec-007); use disposable credentials under [CON-04](../../product-vision.md#con-04).
The prototype does not enforce unequal credential values; configuring distinct values is a precondition.

### Artifact

The authorization boundary of `/admin/plugins` and its per-plugin routes.

### Response

The gateway shall deny administration without the configured admin bearer and leave plugin files and saved configuration unchanged.
An absent configured admin key shall disable administration rather than fall back to the gateway credential.

### Response Measure

For each of the six operations, missing credentials, a wrong bearer, the gateway bearer, and Basic authentication return exactly 401 when an admin key is configured.
With the admin key unset or empty, each operation returns exactly 503, including requests carrying a formerly valid admin key.
Configuration bytes and plugin source files match the pre-request snapshot after every denial; an authorized listing returns 200 when configured.
Any mismatched status or saved-state change fails the scenario; malformed-request validation precedence is outside this check.
