# ADR-007: Emit analytics events from the Gateway and Plugin Manager to a self-hosted Prometheus backend

**Status:** Accepted
**Containers:** Gateway, Plugin Manager
**Addresses:** FR-007
**Decision:** The Gateway and Plugin Manager emit Prometheus metrics for the core task's events; a self-hosted Prometheus backend scrapes them, and Grafana reads from Prometheus for dashboards.

## Context and Problem Statement

The team needs to measure whether the product delivers its value proposition. Metrics must come from the containers that process requests, and the backend must be self-hosted on the university VM.

## Considered Options

1. **Log-only analytics** — rejected: no aggregate queries, no dashboards without extra tooling.
2. **Third-party SaaS analytics** — rejected: data leaves the university VM, privacy risk.
3. **Prometheus scrape + Grafana dashboards** — chosen: self-hosted, standard, supports the queries in `docs/analytics.md`.

## Decision Outcome

Chosen option: **Option 3**. The Gateway (Java) and Plugin Manager (Python) expose Prometheus metrics; Prometheus scrapes them; Grafana renders the charts defined in `docs/analytics.md`.

### Consequences

- **Good:** Self-hosted, standard tooling, supports the metric tree and event table.
- **Bad:** Prometheus is not a container of the product — the product works with collection off. The backend is an external system in the Container View.
- **Quality attributes accepted:** None directly; the analytics capability is traced through FR-007.
