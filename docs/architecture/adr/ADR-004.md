# ADR-004: Keep prototype administration in one Python process

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `prototype gateway`
- **Addresses:** [FR-01](../../functional-requirements/fr/FR-01.md), [QR-03](../../quality-requirements/qr/QR-03.md), [QR-05](../../quality-requirements/qr/QR-05.md)

## Context

The runnable prototype already composes Python middleware inside a FastAPI application.
Plugin administration needs access to the same plugin directory and configuration.
This record documents the implemented prototype boundary, not approval to replace the Java gateway and separate interpreter in [ADR-001](ADR-001.md) and [DEC-011](../../decisions.md#dec-011-tech-stack).
The options below are reconstructed comparisons, not a claim that the team voted on each one.

## Considered Options

- A separate FastAPI router inside the prototype process: reuse configuration parsing and HTTP infrastructure.
- A separate administration service: requires shared storage coordination and another deployment before there is a need for independent scaling.
- Implement administration in the planned Java gateway first: delays validating the existing Python prototype and requires a defined interpreter protocol.

## Decision Outcome

Chosen option: a separate router in the existing Python process.
The `prototype gateway` uses Python 3.12+, FastAPI and Uvicorn, with Pydantic models, local TOML configuration, and trusted single-file plugins.
The router lives in `prototype/gateway/admin.py` and is imported by `prototype/gateway/app.py`.
The plugin directory and TOML file are process-owned files, not separately deployed stores.
A configured OpenAI-compatible provider is external; the demo provider can substitute for it locally.

## Consequences

- Maintainability / Testability ([QR-03](../../quality-requirements/qr/QR-03.md)): tests exercise the real app with temporary files and intercepted upstream calls, without deploying an administration service. This does not verify the planned CLI target.
- Reliability / Fault Tolerance ([QR-05](../../quality-requirements/qr/QR-05.md)): administration persists desired state without reinitializing the active chain; [ADR-002](ADR-002.md) defines the required process restart.
- Administration shares the gateway's filesystem permissions and failure boundary. The separate-process isolation target in [QR-02](../../quality-requirements/qr/QR-02.md) is not established by this prototype.
- Run one worker for administration; this choice does not implement the planned distributed architecture or a CLI.
