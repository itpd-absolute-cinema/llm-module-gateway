# FR-011: Expose the quality signal for each runtime requirement to the observability backend

**Status:** Active
**Traces to:** QR-02, QR-04
**Containers:** Gateway, Plugin Manager

## Behavior

1. The Gateway **shall** expose Prometheus metrics for each runtime requirement, tagged with the environment (staging or production).
2. The Gateway **shall** write one structured log line per request with `request_id`, `route`, `outcome`, and `duration_ms`.
3. The Plugin Manager **shall** expose Prometheus metrics for plugin execution success and failure, tagged with the environment.
4. The observability backend **shall** receive these signals and make them queryable for the SLIs defined in `docs/observability.md`.

## Acceptance Criteria

### AC-01: Signals reach the backend

A request through the Gateway produces increments in `request_received_total` and `plugin_chain_completed_total`, and one structured log line with the four fields.

### AC-02: Environment tag present

The Prometheus scrape contains the `environment="staging"` label in staging and `environment="production"` in production.

### AC-03: SLI query returns a value

The query defined for SLI-01 in `docs/observability.md` returns a ratio between 0 and 1 on the staging backend.
