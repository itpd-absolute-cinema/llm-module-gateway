# FR-009: Replace Plugin Options

- **Status:** Active
- **Traces to:** [CON-01](../../product-vision.md#con-01), [DEC-001](../../decisions.md#dec-001-hot-reload-ruled-out), [ADR-002](../../architecture/adr/ADR-002.md), [ADR-003](../../architecture/adr/ADR-003.md), [ADR-006](../../architecture/adr/ADR-006.md)
- **Containers:** `prototype gateway`

## Behavior

When an authorized administrator supplies a TOML-representable options object for an existing plugin, the gateway shall replace that plugin's entire saved options object while preserving its enabled state and unrelated configuration.
When those options belong to a running plugin, the gateway shall keep using its startup options until restart.
When submitted options cannot be saved in TOML, the gateway shall reject them without changing saved state.
The current PUT API shall accept one optional `before` or `after` name alongside the required options object, placing the entry immediately next to that configured local target, including a disabled target.
Without a hint, or with JSON `null` hints, an existing entry shall retain its position; a source-only local plugin shall receive a disabled entry at the requested position or at the end when no hint is supplied.
The gateway shall save options and placement together or reject both, without importing the plugin or changing the running pipeline; placement is a one-time move, not a persistent dependency.
This behavior runs in the current [administration API](../../api/plugin-management.md); it does not claim an implemented CLI options command.

## Acceptance Criteria

### AC-01

For each saved enabled state, PUT `/admin/plugins/example` with `{"options":{"message":"new"}}` replaces `{"message":"old","metadata":{"tag":"remove"}}` and returns 200 with only the new options.
The PUT response contains saved `{name, enabled, options}` with no `restart_required` body field
and agrees with reloaded TOML. The enabled flag, other plugins, their order, and upstream settings remain unchanged.
`{"options":{}}` clears all options rather than merging them.

### AC-02

With a running responder using `message="old"`, saving `message="new"` leaves chat responses at `old` until restart, then changes them to `new`.
GET likewise returns the startup options with `restart_required: true` before restart,
then the new options with `restart_required: false` afterward.
Editing an inactive, disabled plugin retains its saved options through restart without loading it
or requiring a restart. GET returns `enabled: false`, `options: {}`, and `restart_required: false`.

### AC-03

Options containing `null` return 422 without changing saved state; an unknown plugin name returns 404.
TOML-representable but factory-incompatible options can be saved without invoking the factory; incompatibility is reported at startup, not during the update.

### AC-04

Starting with saved order `[first, example, last]`, PUT `/admin/plugins/example` with `{"options":{"message":"new"},"before":"first"}` returns 200 and saves `[example, first, last]` with only the new options and the original enabled state.
A subsequent PUT with the same options and `after: "last"` saves `[first, last, example]`; repeating it without intervening changes leaves configuration unchanged.
Other entries retain their settings and relative order; omitted or `null` hints on later options replacements preserve the updated position.
For a running plugin, its options and runtime order remain unchanged until restart.
For a source-only local plugin, PUT creates a disabled entry with the supplied options and placement without importing it.

### AC-05

With otherwise valid input, both non-null hints, a self-reference, or an invalid target name return 400; a target without a configuration entry returns 404; multiple matching target entries return 409.
PUT with a hint but no options object returns 400; options containing `null` with a valid hint return 422 without moving the entry.
Rejected replacements leave options, enabled state, configuration order, source files, and the running handler unchanged.
An external configuration edit returns 409, and a recoverable configuration-replacement failure returns 500, without partially replacing options or moving the plugin; retrying after removing the recoverable fault succeeds.
