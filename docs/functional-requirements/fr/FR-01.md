# FR-01: DevOps uploads a new plugin through the CLI

**Status:** Active
**Traces to:** TOS-02 (Plugin Manager discovers and executes an example plugin); Main goal "Support a modular, extensible plugin system"
**Containers:** CLI, Gateway, Plugin Manager.

## Behavior

1. The CLI **shall**, when a DevOps engineer runs `cli plugin upload <path-to-plugin-file>`, send the plugin file to the Gateway's plugin management API.
2. The Gateway **shall**, upon receiving a valid plugin file, forward it to the Plugin Manager, which **shall** store it in the Plugin Store and register it by its plugin name.
3. The Gateway **shall** return a success response containing the registered plugin name, or an explicit error if the file is invalid or the name already exists.

## Acceptance Criteria

### AC-01: Valid plugin is stored and registered

Upload a valid single-file plugin `example_filter.py` via `cli plugin upload example_filter.py`. The Plugin Store contains the file, and `cli plugin list` returns `example_filter` with status `disabled` (default for new plugins).

### AC-02: Duplicate name is rejected

Upload the same plugin file again. The Gateway returns HTTP 409 with an error body naming the existing plugin, and the Plugin Store still contains exactly one copy.
