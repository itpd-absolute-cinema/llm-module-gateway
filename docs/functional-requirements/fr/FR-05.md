# FR-05: DevOps deletes a plugin by name through the CLI

**Status:** Active
**Traces to:** Main goal "Support a modular, extensible plugin system"; lifecycle management of plugins
**Containers:** CLI, Gateway, Plugin Manager.

## Behavior

1. The CLI **shall**, when a DevOps engineer runs `cli plugin delete <name>`, send a delete request for that plugin name to the Gateway's plugin management API.
2. The Gateway **shall** remove the named plugin's saved configuration and file from the Plugin Store only if it is saved as `disabled` and absent from the running pipeline, without changing the Plugin Manager's runtime registry.
3. The Gateway **shall** return an error if no plugin with that name exists, HTTP 409 if it is saved as `enabled` or still running, and a success response otherwise.

## Acceptance Criteria

### AC-01: Deleted plugin disappears from list and store

Upload and enable a plugin, restart the plugin runtime, then disable it and restart again before running `cli plugin delete <name>`. `cli plugin list` no longer contains it, and the Plugin Store directory no longer contains its file.

### AC-02: Deleting a non-existent plugin returns an error

Run `cli plugin delete does-not-exist`. The Gateway returns HTTP 404 with an error body, and the CLI exits non-zero.

### AC-03: Enabled or still-running plugin cannot be deleted

Enable a plugin and attempt deletion before restart; the Gateway returns HTTP 409 without changing its file or saved configuration. Restart to load it, then disable it and attempt deletion before another restart; the Gateway again returns HTTP 409 without changing saved state. Deletion succeeds only after restart excludes it.
