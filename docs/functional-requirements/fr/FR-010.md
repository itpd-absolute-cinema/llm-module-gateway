# FR-010: Record an event for each step of the core task

**Status:** Active
**Traces to:** QR-01, VP-01 (analytics capability)
**Containers:** Gateway, Plugin Manager

## Behavior

1. The Gateway **shall**, upon receiving a client request, increment the `request_received_total` counter with the fields defined in `docs/analytics.md`.
2. The Gateway **shall** increment `plugin_chain_started_total`, `plugin_chain_completed_total`, and `failure_policy_applied_total` at the corresponding points of request processing.
3. The Plugin Manager **shall** increment `plugin_executed_total` for each plugin invocation, with the fields defined in `docs/analytics.md`.
4. Every event **shall** carry a `source` field from the closed set defined in `docs/analytics.md`, and **shall not** carry any personal data. A random UUID is attached to the structured log of each request for correlation and is never used as a Prometheus label.
5. Events with `source=smoke` **shall** be excluded from every metric defined in `docs/analytics.md`.

## Acceptance Criteria

### AC-01: All core-task events fire
Run a request through the Gateway with one enabled plugin. The Prometheus scrape contains increments for `request_received_total`, `plugin_chain_started_total`, `plugin_executed_total`, and `plugin_chain_completed_total`, all with `source=gateway` or `source=plugin_manager`.

### AC-02: Smoke events excluded from metrics
Send a `smoke_test_total` increment with `source=smoke`. The focus metric does not change; a non-smoke increment of the same type does change it.

### AC-03: No personal fields
Inspect the event schema in `docs/analytics.md`. No field is named after a person or carries an email, username, or IP address. `request_id` appears only in logs, not in Prometheus labels.
