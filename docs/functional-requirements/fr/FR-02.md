# FR-02: DevOps lists all plugins and their statuses through the CLI

**Status:** Active
**Traces to:** Main goal "Allow new plugins to be integrated without redesigning the entire gateway"; observability of plugin state
**Containers:** CLI, Gateway, Plugin Manager

## Behavior

1. The CLI **shall**, when a DevOps engineer runs `cli plugin list`, request the full plugin list from the Gateway's plugin management API.
2. The Gateway **shall** return, for each registered plugin, its name and its current status (`enabled` or `disabled`), sourced from the Plugin Manager.
3. The CLI **shall** display the returned list in a readable table with one row per plugin.

## Acceptance Criteria

### AC-01: Empty registry returns an empty list

With no plugins uploaded, run `cli plugin list`. The CLI prints a header row and no data rows, and exits with code 0.

### AC-02: Status reflects current state

Upload two plugins, enable one via `cli plugin enable <name>`, then run `cli plugin list`. The output shows the enabled plugin with status `enabled` and the other with `disabled`.
