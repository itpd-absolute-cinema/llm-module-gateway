# FR-06: LLM requests pass through all enabled plugins before reaching the provider

**Status:** Active
**Traces to:** TOS-01 (Gateway accepts an API request); Main goal "Filter and validate LLM requests and responses"; Main goal "Support a modular, extensible plugin system"
**Containers:** Gateway, Plugin Manager

## Behavior

1. The Gateway **shall**, upon receiving an LLM request from a client, invoke the Plugin Manager over HTTP with the request payload before contacting any LLM provider.
2. The Plugin Manager **shall** execute **all plugins that were `enabled` in the startup snapshot**, in that snapshot's configured order, and return a combined decision to the Gateway.
3. A plugin **shall** be able to allow the request unchanged, modify the request payload, or block the request.
4. The Gateway **shall** forward the (possibly modified) request to the LLM provider only if the plugin chain returns allow; on block, the Gateway **shall** return an error to the client and **shall not** contact the provider.
5. The Gateway **shall** pass the provider's response back through the same plugin chain before returning it to the client, so plugins can also inspect or modify responses.
6. While the Plugin Manager is restarting, the Gateway applies the configured failure policy.

## Acceptance Criteria

### AC-01: Only enabled plugins run

Upload two filter plugins, enable only plugin A, and restart the plugin runtime. Send a request that plugin A would modify and plugin B would block. The provider mock receives the request modified by A and not blocked by B.

### AC-02: Chain runs in configured order

Enable two modifying plugins A (append "-A") and B (append "-B") with A before B, then restart the plugin runtime. The provider mock receives a message ending in "-A-B".

### AC-03: Block stops the request before the provider

Enable a plugin that blocks any request containing "forbidden", then restart the plugin runtime. Send such a request. The client receives an error, and the provider mock log contains no outbound request.

### AC-04: Response passes back through the chain

Enable a plugin that appends "-resp" to the response body, then restart the plugin runtime. Send a request. The client receives the provider response with "-resp" appended.
