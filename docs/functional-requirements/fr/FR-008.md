# FR-008: Separate Admin Authorization

- **Status:** Active
- **Traces to:** [DEC-007](../../decisions.md#dec-007), [CON-04](../../product-vision.md#con-04), [ADR-005](../../architecture/adr/ADR-005.md)
- **Containers:** `prototype gateway`

## Behavior

When a caller submits a valid-shaped plugin administration request, the gateway shall authorize it only with the configured admin bearer credential, independently of chat authentication.
When the admin credential is unconfigured, the gateway shall reject the request with HTTP 503.
When the admin credential is configured but the supplied credential is missing or wrong, the gateway shall reject the request with HTTP 401.
Operators must configure distinct admin and gateway credentials; the prototype does not enforce that their values differ.

## Acceptance Criteria

### AC-01

Configure distinct `GATEWAY_ADMIN_API_KEY` and `GATEWAY_API_KEY` values.
For list, inspect, upload, replace-options, set-enabled, and delete requests with valid paths and bodies, missing credentials, a wrong bearer, the gateway bearer, and Basic authentication each return 401 without changing plugin files or configuration.

### AC-02

With the admin key unset or empty, the same valid-shaped requests return 503, including requests carrying the gateway key or a previously valid admin key.
No request changes saved state.

### AC-03

With the correct admin bearer, listing returns 200.
After disabling chat authentication and restarting, unauthenticated chat can reach a local responder, but administration still returns 401 without the admin bearer and 200 for an authorized listing.
All credentials in these checks are disposable test values, not published secrets.
