# FR-03: DevOps enables a plugin by name through the CLI

**Status:** Active
**Traces to:** Main goal "Filter and validate LLM requests and responses"; configurable plugin activation
**Containers:** CLI, Gateway, Plugin Manager

## Behavior

1. The CLI **shall**, when a DevOps engineer runs `cli plugin enable <name>`, send an enable request for that plugin name to the Gateway's plugin management API.
2. The Gateway **shall** save the named plugin as `enabled` in the Plugin Store without changing the running pipeline. The Plugin Manager **shall** load the saved enabled plugins, options, and order only at startup, so activation requires a runtime restart.
3. The Gateway **shall** return an error if no plugin with that name exists, and a success response otherwise.

## Acceptance Criteria

### AC-01: Enabled plugin becomes active after runtime restart

Upload a filter plugin, leave it disabled, send a request that the filter would block — the request passes through. Run `cli plugin enable <name>` and send the same request again; it still passes through. Restart the plugin runtime and send it again; the request is now blocked.

### AC-02: Unknown plugin name returns an error

Run `cli plugin enable does-not-exist`. The Gateway returns HTTP 404 with an error body, and the CLI exits non-zero.
