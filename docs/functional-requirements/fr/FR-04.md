# FR-04: DevOps disables a plugin by name through the CLI

**Status:** Active
**Traces to:** Main goal "Enable configurable policies"; operational control over active plugins
**Containers:** CLI, Gateway, Plugin Manager

## Behavior

1. The CLI **shall**, when a DevOps engineer runs `cli plugin disable <name>`, send a disable request for that plugin name to the Gateway's plugin management API.
2. The Gateway **shall** instruct the Plugin Manager to mark the named plugin as `disabled`, so that it no longer participates in request processing.
3. The Gateway **shall** return an error if no plugin with that name exists, and a success response otherwise.

## Acceptance Criteria

### AC-01: Disabled plugin stops affecting requests

Enable a blocking filter plugin and confirm a request is blocked. Run `cli plugin disable <name>`, send the same request — it now passes through to the LLM provider.

### AC-02: Status is persisted across requests

After disabling, run `cli plugin list`. The plugin appears with status `disabled`. The disabled state remains after a Gateway restart.
